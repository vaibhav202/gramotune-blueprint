# 03 — Engine spec (Dart audio engine)

Status: v0.1 (2026-10-31). Spikes S1–S3 confirm or change items marked **[verify]**.
Packages: `engine_api` (interfaces, no FFI) and `engine` (implementation, FFI to AAudio and the NDK media APIs).

## 1. Goals

1. Gapless, glitch-free local playback of MP3, AAC/M4A, FLAC, Vorbis, Opus, WAV (list confirmed by S2).
2. A bit-transparent default signal chain; DSP only when the user enables it.
3. Accurate position, fast seek, robust recovery (route changes, bad files).
4. Output behind an interface so exclusive, USB and root backends (D-series) plug in later without UI changes.
5. Everything runs headless on a desktop Dart VM with fake backends, so agents can test it without a phone.

## 2. Public API (`engine_api`)

```dart
final class PlayItem {
  final String id;           // library track id
  final String uri;          // file path, content:// or http://127.0.0.1:<port>/… (remote proxy, Y-series)
  final int? startUs, endUs; // segment bounds (CUE, v1.1); null = whole file
  final double? gainDb;      // resolved ReplayGain gain for the active mode, if any
  final double? peak;        // linear peak for clipping protection
  final int? durationUs;     // hint only
}

sealed class EngineCommand {
  // LoadWindow(items, startIndex, startPositionUs, autoplay) · AppendItems(items) · Play · Pause · Stop
  // SeekTo(us) · SkipTo(index) · SetRepeatOne(bool) · SetStopAfterCurrent(bool)
  // SetDsp(DspConfig) · SetOutput(OutputConfig) · Release
}

sealed class EngineEvent {
  // StateChanged(state) · ItemChanged(index, id, reason) · PositionTick(positionUs, bufferedUs)
  // NeedMoreItems(afterIndex) · ItemFailed(id, reason) · SignalPath(info) · QueueEnded · EngineError(err)
}

enum PlaybackState { idle, preparing, playing, paused, ended, error }

abstract interface class EngineClient {
  Stream<EngineEvent> get events;
  PlaybackState get state;
  Future<void> send(EngineCommand command);
}
```

The window protocol (D-022): the UI isolate owns the full queue and sends a window of up to ~500 items. The engine emits `NeedMoreItems` when 50 or fewer items remain.

### Backend and decoder interfaces

```dart
abstract interface class OutputBackend {
  OutputCapabilities get capabilities;              // rates, formats, sharing modes, exclusive/MMAP support
  OutputStreamInfo open(OutputRequest request);     // returns the format actually granted
  int write(PcmBuffer pcm, int frames, {required Duration timeout}); // frames accepted, negative = OutputError
  void start(); void pause(); void flush(); void close();
  PresentedPosition? presentedPosition();           // (framePosition, monotonicNanos) from the device
  int get xrunCount;
}

abstract interface class Decoder {
  DecoderInfo open(PlayItem item);                  // format, duration, gapless hints, codec name
  int read(PcmBuffer out, int maxFrames);           // frames, endOfStream, or error code
  void seekTo(int us);
  void close();
}
```

Both interfaces are synchronous and blocking by design: they run on the engine isolate's thread.

## 3. Threading and the pump loop

- One engine isolate. No native thread calls back into Dart (D-005): `NativeCallable.listener` is async and void-only, and `isolateLocal` must run on the creating thread.
- The **pump** decodes about 100 ms per iteration, processes DSP, writes with a short timeout (≤20 ms), then yields to the event loop (`await Future.delayed(Duration.zero)`), so commands are served within ~50 ms.
- Output buffer capacity target: ~500 ms; buffered-ahead target: 200–400 ms (configurable). The deeper buffer absorbs GC pauses and UI jank.
- Blocking native calls are never `isLeaf: true` (AGENTS §6.3).
- Event cadence: `PositionTick` ≤10 Hz with the UI visible, ≤1 Hz otherwise; other events only on change.

```
loop while state == playing:
    n = decoder.read(buf, chunkFrames)          // EOS → timeline.advance() (gapless, §5)
    dsp.process(buf, n)                         // no-op when everything is off
    out = convert(buf, n)                       // only if output format differs
    written = backend.write(out, n, timeout: 20ms)   // may be partial → keep remainder in carry buffer
    if written < 0 → recovery(§9)
    await yieldToEventLoop()
```

## 4. Decoder (NDK media, FFI)

- Bindings generated by `ffigen` from the NDK headers for `AMediaExtractor`, `AMediaCodec`, `AMediaFormat` (library `libmediandk.so`).
- Source: `AMediaExtractor_setDataSourceFd` for `content://` URIs (open fd via `platform_android`) and for files; an `http://127.0.0.1` URL for the remote proxy.
- Flow: select the first audio track → read format (`mime`, `sample-rate`, `channel-count`, `durationUs`, `encoder-delay`, `encoder-padding`, `pcm-encoding`) → `AMediaCodec_createDecoderByType` → configure with a request for **float PCM** where available → start → loop: queue input from the extractor, dequeue output, copy to the preallocated `PcmBuffer`.
- Handle `OutputFormatChanged` (rate, channels, encoding can change after the first output buffer).
- **[verify, S2]** Whether the platform FLAC decoder honors `pcm-encoding = float` for 24-bit sources on the target devices. If not, 24-bit FLAC is truncated to 16-bit by the platform, which breaks the hi-res goal. Fallback plan (needs owner approval, D-004): a small bundled C decoder (for example dr_flac) built via Dart build hooks, behind the same `Decoder` interface.
- Formats the platform does not decode (for example APE, WavPack, DSD, AIFF): out of scope for v1.0; the `Decoder` interface allows plugins later.
- Codec selection records the decoder name in Signal Path (hardware vs software, `c2.android.*`).
- All native handles are wrapped in owner classes with idempotent `close()`; leak counters are exposed in diagnostics.

## 5. Gapless

Per item the engine needs `leadingTrimFrames` and `trailingTrimFrames`.

1. Sources, in order: MediaFormat `encoder-delay` / `encoder-padding` when the extractor provides them; container tags otherwise (MP3 LAME/Xing header, MP4 `iTunSMPB`); Opus pre-skip; FLAC, Vorbis and WAV need none. **[verify, S3]** Reports about whether MediaCodec trims by itself conflict, so S3 measures boundaries with test fixtures instead of trusting either claim.
2. Trailing trim uses a tail hold-back of `trailingTrimFrames` frames that is discarded at end of stream.
3. The next item is prepared while the current one plays (extractor and codec open, first chunk decoded). At end of stream the engine appends the next item's frames (after its leading trim) directly into the same output stream.
4. If the next item's output format (rate, channels, sample encoding) differs, the engine drains, closes and reopens the stream (D-006). A brief gap is accepted and documented in Signal Path.
5. Repeat-one and stop-after-current are handled inside the engine, because they must stay gapless-safe.

Acceptance: gapless suite passes for FLAC, MP3 (LAME tag), AAC (iTunSMPB) and Opus fixture pairs: sample-continuous sine across the boundary and exact total frame count (`docs/08-testing-spec.md` §4).

## 6. Output (AAudio via FFI)

Stream configuration for the default `AAudioShared` backend:

| Setting | Value | Note |
|---|---|---|
| Direction, usage, content type | output, `AAUDIO_USAGE_MEDIA`, `AAUDIO_CONTENT_TYPE_MUSIC` | |
| Sharing mode | shared | exclusive is a D-series experiment |
| Performance mode | power-saving by default | S1 compares with "none" for battery and xruns; low-latency is for exclusive/MMAP only |
| Rate and channels | the item's own | the framework resamples if the hardware rate differs (D-006) |
| Format | `PCM_I16` for 16-bit sources, `PCM_FLOAT` otherwise | `PCM_I24_PACKED` / `PCM_I32` exist from API 31 and become options in the D-series **[verify]** |
| Buffer capacity | ~500 ms | request, then read back what was granted |

Rules:
- After `openStream`, read back rate, channels, format and buffer sizes and convert if anything was not granted. The platform documentation requires this.
- Use blocking writes with a timeout from the pump. A negative result is an `aaudio_result_t`; the disconnect case triggers recovery (§9).
- `requestPause` then `requestFlush` for seek and stop; `waitForStateChange` with a timeout to confirm transitions. Never close a stream while another thread waits on it.
- Count xruns with `AAudioStream_getXRunCount` and expose them.
- `AAudioStream_isMMapUsed` lives in a testing header; resolve it with `dlsym` and treat absence as "unknown" **[verify]**.

**Presentation clock**: position is computed from `AAudioStream_getTimestamp` (framePosition at a monotonic time) extrapolated to "now", minus the output-frame offset where the current item started. After pause, flush or seek the engine records a new base. **[verify, S1]** how the frame counters behave across flush; the clock has unit tests with a fake backend and a manual time source.

## 7. DSP chain

All in float32 with float64 filter state. The chain is skipped entirely when disabled.

1. **ReplayGain**: apply `gainDb` plus preamp. Clipping protection limits the gain to `-20·log10(peak)` when peak is known. Default **off** in v1.0 (bit-transparent default).
2. **Equalizer**: 10 peaking biquads at 31, 62, 125, 250, 500, 1k, 2k, 4k, 8k, 16k Hz, Q ≈ 1.41, ±12 dB, plus preamp and an "auto preamp" option that offsets the largest boost. Direct Form II transposed; parameter changes crossfade over ~10 ms to avoid zipper noise. Bypassed when all gains and the preamp are zero.
3. **Dither**: TPDF only when narrowing float to 16-bit after any DSP. Never applied on the transparent path.
4. **Transition fades**: 10 ms fade-out before pause or seek and fade-in after start, to avoid clicks. Signal Path states that the chain is transparent except for these transition fades.
5. Volume: no software volume by default. The in-app slider mirrors Android's system volume (D-007).

## 8. Seeking and position

- Seek: `AMediaExtractor_seekTo` with the previous-sync mode, `AMediaCodec_flush`, then decode and discard until the target timestamp (a small pre-roll handles MP3 bit reservoir).
- Accuracy depends on the extractor (VBR MP3 without a seek table is approximate); document the measured error per format in S3.
- Output side: pause, flush, then restart with a fade-in.

## 9. Errors and recovery

| Condition | Detection | Action |
|---|---|---|
| Output disconnected (unplug, route change) | write returns the disconnect error | close; if it was a headphone unplug emit `Paused(reason: routeLost)`; otherwise reopen and resume from the presented position; after 3 failures in 2 s pause and report |
| Output open fails for a format | `open` error | fallback chain: swap I16/float → let AAudio choose the rate and resample in the engine (flag "resampled" in Signal Path) → report error |
| Decoder error mid-item | codec or extractor error | if ≥1 s was decoded treat as end of item, else emit `ItemFailed` and advance |
| Source unreadable | open error | `ItemFailed(reason)`, advance; the controller marks the track |
| Underrun | xrun counter rises | raise buffered-ahead target by 100 ms up to 800 ms; log |
| Engine isolate exit | controller sees the exit port | restart, reload the window at the last position, log to diagnostics |
| Audio focus lost | controller (docs/05) | pause or duck per policy |

No empty `catch`. Every failure produces an `EngineError` or `ItemFailed` event with a stable reason code.

## 10. Performance budgets (provisional, baseline in M1)

- Decode plus DSP at 44.1 kHz stereo: ≤5% of one core on POCO M3-class hardware.
- Steady-state wakeups: ≤10 per second.
- Engine heap ≤30 MB; total PCM buffers ≤4 MB.
- Seek to audible: ≤150 ms for local files.

## 11. Diagnostics counters

xruns, buffered-ahead ms, frames written, decode time per chunk (avg and max), pump iteration time (avg and max), open and close counts, live native handle counts, last 50 errors, granted stream info. Exposed through `SignalPath` and the Diagnostics screen (U-13, U-18).

## 12. Test hooks (host, no phone)

- `MemoryOutputBackend`: records written PCM, supports simulated disconnects and underruns, and a manual clock.
- `FakeDecoder`: generates sine or ramp PCM with configurable delay, padding, format and failures.
- `PresentationClock` and the gapless planner are pure Dart with unit tests.
- Decode-dependent tests (real MediaCodec) run as `integration_test` on an emulator or device.
