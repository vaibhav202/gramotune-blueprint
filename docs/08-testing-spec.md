# 08 — Testing spec

Status: v0.1 (2026-10-31). Agents cannot hear audio or see a device screen, so this spec turns as much as possible into machine-checkable evidence and isolates the rest into human checks.

## 1. Layers and where they run

| Layer | Tooling | Runs on | Examples |
|---|---|---|---|
| Unit | `dart test` / `flutter test` | host | sort keys, M3U parser, gapless planner, play-count rule, DSP math |
| Engine scenarios | `dart test` with fakes | host | skip storms, disconnects, underruns, format changes |
| Widget and golden | `flutter test` | host | `ui_kit` widgets per skin, accessibility guidelines |
| Integration | `flutter test integration_test -d <id>` | emulator or device | scan fixtures, play, seek, restart restore |
| Performance | `flutter drive --profile` with timeline summary | device | scroll jank, startup, flip animation |
| Soak and battery | `tool/soak.sh <device>` (adb) | device | 30-minute screen-off run, battery drain |
| Human checks | `docs/human-checks/*.md` | owner | gapless by ear, fades, skin look, ergonomics |

`tool/check.sh` runs analyze, format check, boundary check, token check, docs check and all host tests. CI runs it on every push and runs the emulator integration job nightly and on milestone branches.

## 2. Fixtures (`test_assets/`)

- All audio is **synthesized** (sine sweeps, noise bursts, impulse trains with known sample indices), so there are no copyright issues. Total size under ~5 MB.
- Generated by `tool/gen_fixtures.sh` (needs ffmpeg, flac, lame, opusenc on a dev machine); outputs are committed along with `manifest.json`: file, format, rate, depth, channels, delay and padding values, expected frame count, expected PCM hash or tolerance.
- Matrix: FLAC (16/44.1, 24/96), MP3 (CBR and VBR with LAME tag, one without Xing), AAC in M4A (with `iTunSMPB`), Opus (48 kHz), Vorbis, WAV (16/44.1).
- "Weird files" set (synthetic): unicode and empty tags, ID3v2.2, huge cover art, truncated file, 0-byte file, wrong extension, tag-only file.

## 3. PCM golden tests

Purpose: prove the decode path and the transparent signal chain.

- **Lossless (FLAC, WAV)**: decode with the engine into `MemoryOutputBackend`; the SHA-256 of the output samples must equal the manifest hash (computed by the generator from the source samples). This also asserts bit-transparency for 16-bit sources with DSP off.
- **24-bit FLAC**: if S2 shows the platform decoder cannot deliver full depth, this test fails by design and drives the D-004 decision.
- **Lossy (MP3, AAC, Opus, Vorbis)**: decoders are not bit-identical, so compare against reference PCM from ffmpeg after aligning by the known delay: RMS error below −60 dBFS and exact frame count after trimming.
- **DSP**: EQ and ReplayGain verified numerically (gain at band centers within 0.1 dB; unity when bypassed; clipping protection holds peak ≤ 1.0).
- Failing golden tests block merges of changes to `engine`.

## 4. Gapless suite

Fixture design: consecutive tracks carved from one continuous sine, so the sample index is known across the boundary.

For each pair (FLAC→FLAC, MP3→MP3 with LAME tags, AAC→AAC with `iTunSMPB`, Opus→Opus):
1. Play both items through the engine into `MemoryOutputBackend`.
2. Assert the total frame count equals the sum of the trimmed lengths.
3. Assert phase continuity across the boundary: max |Δsample| at the join does not exceed the sine's natural slope plus a small epsilon, and no zero run longer than 0 frames appears.
4. Assert exactly one stream open when formats match, and a reopen when they differ (rate-change pair).

Real-decoder variants run as integration tests; the planner logic also runs on the host with `FakeDecoder`.

## 5. Engine scenario tests (host)

State machine and timeline properties, using `FakeDecoder`, `MemoryOutputBackend` and a manual clock:
- skip storm (100 `SkipTo` in 1 s) leaves a consistent state and no leaked handles;
- seek during prepare, seek past the end, seek to 0;
- device disconnect during playback and during pause;
- underrun injection raises the buffered-ahead target as specified;
- repeat-one and stop-after-current at the last item;
- window exhaustion emits `NeedMoreItems` and ends cleanly;
- invariants: position never negative or decreasing without a seek; frames written equal frames decoded minus trims; native handle counters return to zero after `Release`.

## 6. Library tests

Unit tests per the library spec §10, plus benchmarks on the synthetic 50k library. Thresholds (provisional): lens first page <200 ms, search <50 ms, unchanged rescan <5 s for 20k files. Benchmarks print numbers into the CHANGELOG entry; regressions beyond 20% need an explanation.

## 7. UI tests

- Golden images for each `ui_kit` widget in Classic and Plain skins, at 1× and 2× font scale. Test fonts are bundled so goldens are deterministic.
- Flutter accessibility guidelines on key screens: `androidTapTargetGuideline`, `labeledTapTargetGuideline`, `textContrastGuideline` (Plain skin must pass; Classic reports and tracks failures).
- Screen smoke tests with fake providers (no engine, no database).
- Responsive checks at 360, 412, 600 dp widths and 200% text scale.

## 8. Integration tests (device or emulator)

Scenarios: first-run permission flow (with granted permissions pre-set by `adb`), scan a pushed fixture folder, play, pause, seek, skip, queue operations, kill and relaunch restore, "Open with" intent via `adb shell am start`, notification actions via `adb shell cmd media_session` where available **[verify]**.
Emulators prove functional behavior only; glitch-free output is judged on real hardware.

Host note (2026-11-08): the emulator installed on the development host crashes inside `libgfxstream_backend.so` under every GPU backend, so integration tests currently run on the POCO M3 (`docs/dev-environment.md`, section 4). Keep the command device-agnostic (`-d <id>`); the nightly CI job (M0.4) supplies its own emulator.

## 9. Soak and battery protocol (`tool/soak.sh`)

1. Install the release-mode build, push a playlist of fixtures (or the owner's own files).
2. Start playback with a media key; turn the screen off.
3. For 30 minutes: perform one random seek per minute using media-session commands; sample `dumpsys media.audio_flinger` and `dumpsys media_session`; fetch engine diagnostics (xruns, buffer fill, memory) through a debug broadcast or the exported log.
4. Pass: 0 xruns, memory within ±5%, no process death, position progress consistent with wall clock.
5. Battery: `dumpsys batterystats --reset`, run one hour screen-off on the same device with a reference player and with this app; report both in the CHANGELOG (target ≤1.5× the reference).

## 10. Static checks

- `tool/check_boundaries.dart`: package import matrix from AGENTS §5.
- `tool/check_tokens.dart`: no literal colors outside `skin`/`ui_kit`; no `print(`; no `isLeaf: true` in `engine` unless the function is on the allowlist of pure functions; no Kotlin or Java sources outside the allowed paths.
- `tool/check_docs.py`: every `§n` reference, ADR id, requirement, quality, screen, risk and milestone id used in the docs must resolve to a definition; keeps the specs coherent while many agents edit them.
- Analyzer with `flutter_lints` (or a stricter set chosen in M0.1); zero warnings.

## 11. Coverage and merge gates

- Pure-Dart `engine` and `music_library` logic: ≥80% line coverage.
- `ui_kit`: every widget has a golden test.
- A milestone item is done only when its listed tests exist and pass, evidence is pasted in the CHANGELOG entry, and any human check is either recorded as passed or the item stays 🟡.

## 12. Human checks

Template: `docs/human-checks/TEMPLATE.md`. Typical items per milestone:
- Listening: no clicks at gapless boundaries, pause/resume and seek are click-free, EQ sounds sane, volume behavior is safe.
- Visual: skin matches the Figma frames, flip animation is smooth, text is legible on a real screen.
- Ergonomics: one-hand reach, tap targets, index scrubber accuracy.
- Real-world: Bluetooth car stereo, wired IEMs, USB DAC.

Results are recorded in the file and summarized in the CHANGELOG.
